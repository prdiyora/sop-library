🛠️ 8.6 — Technical SEO Audit (Screaming Frog Crawl)

Dabbo 08 · Technical SEO · ✅ Done

6 Month Plan na Month 1 ma "full audit" lakhel chhe - aa doc te audit kevi rite karvo te batave. Audit = list of issues nahi, priority sathe action plan.

8.6.A Steps

  1. Crawl: Screaming Frog (free 500 URLs) ma domain nakho. Mode: Spider.
  2. Response codes: 3xx, 4xx, 5xx ni list (Technical point 03).
  3. Indexability: noindex, canonicalised, blocked pages - intentional chhe? (Technical point 01, 02).
  4. Page titles + meta: missing, duplicate, limit karta vadhare lamba.
  5. H1: missing, ek karta vadhare, duplicate.
  6. Images: alt text missing, size moto.
  7. Crawl depth: money pages 3 clicks thi vadhare deep na hova joiye.
  8. GSC data sathe match: Pages report, Core Web Vitals, manual actions, security issues.

8.6.B Priority kevi rite nakki karvi

  • Critical: site/money pages index nathi, noindex/robots bhool, site-wide redirect issue - tarat
  • High: money pages par duplicate/canonical issue, broken internal links, slow mobile
  • Medium: meta missing, alt text missing, redirect chains
  • Low: cosmetic (title thodu lambu)

Rule: "Ketla URLs affected" x "te pages ni business value" = priority. 500 blog tags par missing meta < 5 product pages noindex.

8.6.C Output

  • Sheet: Issue | Example URLs | Count | Impact | Effort | Priority | Owner | Status

8.6.D Checklist

  • Full crawl thai gayu + GSC data sathe cross-check karyu
  • Issues priority sathe listed
  • Critical issues 1 week ma fixed

8.6.F SEMrush Site Audit (Semrush SOP - added 19 Nov 2026)

Complete step-by-step SOP for weekly website auditing, PDF reporting and issue fixes

1. Purpose and weekly schedule

Run a complete SEMrush Site Audit for the Client A website every Monday.

Download the Full Site Audit PDF report and save it in the designated Google Drive folder.

Review every issue listed in the report, prepare a fix list, and complete the fixes that are approved and within scope.

After fixes, verify the affected pages/issues and record the completion status.

WhenRequired activity
Every MondayCreate/run the Site Audit, wait for crawl completion, export PDF.
After report downloadReview issues, prioritize fixes and record affected URLs.
During the weekImplement approved fixes and verify the results.
Next MondayRun the next audit and compare remaining/new issues.

2. Open Site Audit

Log in to the SEMrush shared account.

Open Site Performance / Site Audit from the SEMrush navigation.

Go to the Site Audit page where the Create button is available.

3. If SEMrush shows the website-monitoring limit message

Message to look for: “You’ve reached your limit of websites to monitor.”

Open a separate browser tab and go to https://semrss.jupiterseotool.com/home.

Find the Projects area and search for the project that is no longer needed and is occupying the shared account’s project limit.

Before deleting anything, verify the exact project name/domain and confirm that it is obsolete, unused and not needed by another team member. Do not delete an active project or another person’s required work.

For a confirmed obsolete project, open its three-dot menu and choose Delete.

If the platform requests a confirmation code, follow the on-screen confirmation process and enter the code only in the SEMrush interface. Never share the code in chat or store it in this SOP.

Return to SEMrush Site Audit and refresh the page. Confirm that the website-monitoring limit has been released.

Safety rule: Deleting a project is a destructive action. If the project owner or purpose is unclear, stop and get approval before deleting it. Do not delete a project simply because it appears first in the list.

4. Create a new Site Audit project

On the Site Audit page, click Create.

In the “Website” field, enter the website to audit.

In the “Name” field, enter the business/project name in a clear format.

Wait approximately 2–5 minutes for the next setup section or “New Audit” popup to appear. Actual loading time may vary.

6. Wait for the crawl to finish

After “Preparing to crawl…” appears, wait approximately 15–20 minutes for the crawl to begin and process pages. The actual time depends on site size and crawl conditions.

Return to the /siteaudit page and refresh it after the initial wait.

Check the project’s page count. If it is still increasing, allow more time.

While the count is increasing, refresh/check approximately every 10 minutes.

When the crawled page count stops increasing and the audit status indicates completion, open the project.

Do not treat a temporarily unchanged count as completion if the status still says crawling or processing.

8. Export the Full Site Audit PDF

In the audit report, click the PDF/export option in the corner.

When the “Report template” popup opens, select “Site Audit: Full report”.

Wait approximately one minute for the report template to load.

Leave the “Export settings” unchanged, as specified in this workflow.

In the export options, choose “Download PDF”. Do not choose email sharing or online dashboard unless separately requested.

Save the PDF to the client na designated folder.

Use a consistent filename, for example: Client A-Stone-Site-Audit-YYYY-MM-DD.pdf.

Confirm that the downloaded PDF opens correctly and includes the full report.

9. Review the PDF and prepare the fix list

Read the full PDF from beginning to end. Do not review only the summary score.

List every issue SEMrush reports and capture the affected URL(s), issue description, severity/priority and recommended action where shown.

Group issues by type so that similar fixes can be handled together.

Prioritize critical errors first, then high-priority warnings, then lower-priority notices. Confirm the actual impact before changing the website.

Check whether an issue is valid for the page/site before implementing a fix. Some audit recommendations may not apply to the site’s intended setup.

10. Implement and verify fixes

Work through the approved fix tracker, starting with the highest-impact issues.

Before editing, confirm the affected URL, page type and issue details.

Make the change in the appropriate platform/CMS or technical configuration.

Recheck the affected URL after the change. Confirm that the page still loads and that the fix has not broken another page or function.

Mark the item Fixed only after verification. If it cannot be fixed, record the reason and leave it Open or Not applicable as appropriate.

For issues that require developer access, code changes, redirects, robots directives or server configuration, assign them to the responsible developer rather than making an unreviewed change.

Keep a record of completed fixes and unresolved items for the next Monday audit.

11. Weekly completion checklist

12. Important operating notes

The 1,000-page crawl limit is the requested setting for this process. If SEMrush reports that the site exceeds the limit, record the limitation and agree on the appropriate crawl scope rather than assuming every URL was audited.

The example report showing 139/500 pages is not the expected Client A result. Always record the actual page count and configured limit.

Crawl duration can vary. The 2–5 minute setup wait, 15–20 minute initial crawl wait and 10-minute progress checks are operational estimates from the supplied workflow, not guaranteed SEMrush processing times.

Keep the PDF report and fix tracker together in the same weekly folder so that week-to-week progress can be compared.

Do not delete projects, alter production settings or implement risky technical fixes without confirming ownership, impact and approval.
