5.14.B SEMrush On Page SEO Checker

Step-by-step: collect URL-keyword improvement ideas and verify approved fixes

1. Open the correct website campaign

Open SEO → Other → On Page SEO Checker in the checked navigation. Open the correct existing project or create a campaign only when that project and its quota use are approved.

Confirm domain, owner and target market. Do not delete another project to free a shared-account limit. Do not connect private GSC/GA4 accounts to shared access without specific approval.

2. Set location, device and language

In setup, choose target country/region/city and desktop/mobile. Set language where offered. Check these before collection because changing targeting later may require reconfiguration or a new campaign.

Working example: Skyline Stone's agreed target location and device. Do not assume a US-wide project needs local Surat settings because the operator is in India.

3. Add landing-page and keyword pairs

Choose Manual, File, Auto Import, Organic Rankings or approved GSC import as available. Manual entry pairs one real URL with its target keywords.

For file upload follow the current template. The manual specifies keywords in the first column and landing pages in the second. Remove irrelevant auto-suggestions and avoid assigning the same target keyword to multiple pages.

Real run on 19 Nov 2026: a campaign for skylinestoneproducts.com (United States, English) pairing https://skylinestoneproducts.com/collections/porcelain-sinks with the keyword 'porcelain kitchen sinks' (1 unit). Results: 7 total ideas for the page (Content 5, Backlinks 1, SERP Features 1; Strategy and Semantic 0), keyword Total Volume 720, modeled traffic potential 262 vs current 1. Actual ideas received: add aggregate-rating Product markup; create more informative long-form content; improve readability; add the target keyword to the h1, title and meta description. Passed checks included no cannibalization, no keyword stuffing, and title/meta description matching the live SERP. User Experience ideas need a Google Analytics connection and Technical ideas need Site Audit, both left unconnected.

4. Review units, crawler and schedule

Check the total units consumed before Collect ideas. Imported keyword counts combine across sources. Do not assume this research task authorizes buying additional credits or plan capacity.

Review crawler and re-collection settings. Choose no recurring collection/email unless it is part of the approved project routine. Do not change robots rules or server access simply to force a crawl.

5. Read Overview and Optimization Ideas

After collection finishes, review Overview and Top Pages to Optimize. Open Ideas for each selected landing page.

Inspect relevant Strategy, SERP feature, Content, Semantic, Backlinks, Technical and User Experience ideas where available. Some depend on integrations; unavailable categories are not a clean bill of health.

Potential traffic is a modeled scenario, not a guaranteed outcome.

6. Review competitors before accepting ideas

Open the cited benchmark pages and Top 10 Benchmarking where available. Verify that the comparison matches our keyword and real search intent.

If an idea suggests more content, add genuinely useful information rather than copying the competitor's word count. If it suggests technical changes, confirm the actual issue and get the responsible developer's approval.

7. Track implementation and rerun

Tracker: URL | Target keyword | Location/device | Idea category | Exact recommendation | Evidence | Proposed fix | Owner | Approval | Status | Verification date.

Export ideas to the displayed spreadsheet format where available. Implement only approved changes on the website, check the page still works, then rerun the campaign when permitted. Use Idea Tasks to review progress; a changing idea count is not itself proof of a ranking improvement.

8. Final quality check

This SOP documents the workflow. Creating projects, collecting a full paid/quota-bearing campaign and editing the website require their own approved scope.

Final quality gate (tick karo)

  • Correct domain and keyword-to-URL mapping.
  • Quota, schedule and integration choices approved.
  • Every recommendation checked against real page intent.
  • No unapproved project deletion or production change.
  • Output: prioritized and assigned on-page fix tracker, with rerun evidence when executed.

5.14.C Expected Output

Output: per-page optimization to-do list, priority wise - meta, content, readability, links.
